# 架构与数据契约

本文写给想读懂或改动这份代码的人。核心只有一句话：
**所有环节靠"页级文本 + 页码范围"这条链子串起来，任何一环丢了页码，引用就不可核验。**

---

## 一、数据流

```
10_原始归档/规范教材/<课程>/  10_原始归档/课件/<课程>/  10_原始归档/录音/<课程>/
        │                          │                        │
        │ M1 parse_docs            │ M2 ocr_pages           │ M3 transcribe
        ▼                          ▼                        ▼
   20_文本库/pages.jsonl  ◄────── 回填 text ──────      transcript.jsonl
        │                                              （权重最低，不进 pages）
        │ M4a build_skeleton
        ▼
   30_知识点/skeleton.json   （课 → 章 → 节 + 页码范围）
        │
        │ M4b extract_kp（切块 + LLM 抽取 + 即时引用核验）
        ▼
   kp.jsonl / evidence.jsonl
        │
        │ M5 verify_kp（四档核验 + 一致性审计）
        ▼
   audit.jsonl + kp.status
        │
        │ M6 make_review
        ▼
   40_复习产物/（背诵卡 / 数字对照表 / 脉络展开 / Anki 导入 / 待确认清单）
```

**关键取舍**：录音转写在链子之外。它只作参考，**永远不进 `pages.jsonl`、不作引用来源** ——
因为课堂录音里的话无法作为"教材第 N 页写着什么"的证据。

## 二、核心契约文件

### `20_文本库/pages.jsonl` —— 一切引用的源头

每行一页。必填字段：

| 字段 | 说明 |
|---|---|
| `course` | 课程名（来自素材目录名，经 `kb.match_course` 归一到课表） |
| `source_file` | 相对项目根的文件路径（**引用的"文件"就是它**） |
| `file_id` | 文件身份（同名不同版本时用它区分） |
| `page_no` | **该文件内的**页码（PDF 物理页；EPUB 是节序号） |
| `page_label` | 人读标签（`第N页` / `第N节`） |
| `text` | 页文本（**允许为空**：封面/纯图表页本来就没文本） |
| `source_kind` | `pdf` / `pptx` / `epub` |

> ⚠️ **`page_no` 是「文件内」的，不是全局的。**
> 一门课挂多本书时，各书的页码都从 1 重编 —— 这也是下面「块（chunk）绝不跨文件」
> 这条不变量的由来。

### `30_知识点/skeleton.json` —— 课 → 章 → 节

```jsonc
{ "courses": { "<课程名>": {
    "chapters": [ { "num": 3, "title": "…", "page_start": 76, "page_end": 101,
                    "kind": "body", "sections": [ { "title": "…", "page_start": 76, "page_end": 88,
                                                    "node_id": "…" } ] } ] } } }
```

`kind` 三态（判据**只在** `build_skeleton.classify_kind()` 一处实现）：

| kind | 含义 | 抽取时 |
|---|---|---|
| `body` | 正文 | 抽取 |
| `appendix` | 附录 / 附表（**数值表最密集区**） | 抽取 |
| `matter` | 前言 / 目录 / 索引 / 符号表 / 参考文献 | **跳过** |

### `kp.jsonl` / `evidence.jsonl`

知识点一行一条，证据一行一条（一条知识点可有多条证据）。要点：

- `kp_id` 形如 `<course_id>-KP-0042`；
- 每条 kp 携带 `source_file` + `page_label_start/end` + `chunk_id`；
- `evidence.verify_method` ∈ `exact|partial|fabricated|not_found`；
- `kp.status` ∈ `verified|pending|rejected`；
- 新批次的行带 `run_id`（**旧行永远没有它** —— 不回填，因为旧行没有批次语义）。

### `audit.jsonl` —— 人工复核队列

`priority` ∈ `P0|P1`；`P0` 表示**阻塞背诵材料**的问题（引用找不到、数字对不上、定义过短）。
`status` ∈ `pending|done|ignored`。

## 三、几条必须守的不变量

### 1. 块（chunk）绝不跨文件

每本书的 `page_no` 各自从 1 重编 ⇒ **一个块一旦吃了两本书的页**，
它的 `page_start..page_end` 就是无意义的（会产出 `p561-5` 这种倒挂范围），
而 `chunk_id` 里的文件标签只指向第一本 ⇒ **引用落点会对到错误的文件**。

`kb.build_chunks` 里有显式的文件边界守卫；`selftest` 用**生产路径**复算并断言"零跨作品块"。

> 注意：生产抽取路径 `extract_kp.chunks_from_skeleton` 是**逐文件**调 `build_chunks` 的。
> 试图用"整门课一起喂"来复算，会得出"存在跨作品块"的**假阳性** —— 复算生产行为必须走生产路径。

### 2. 页码双轨

`page_no` 是 PDF 物理页，书上印的是**印刷页码**，两者差一个 offset，**每本书不同**。
引用一律走 `kb.page_ref()`，输出形如：

```
书p294（PDF p311）          ← 有 offset
书p14（PDF 第5节）          ← 锚点区间内（EPUB：节序号与书页不等长，用锚点插值）
书p≈34（PDF 第11节，推算）   ← 锚点区间外，**显式标注"推算"**
PDF p8                      ← 没有映射规则时，**绝不冒充印刷页**
```

> **一个 offset 装不下一门课**：同一目录下 4 本书的 offset 可能是 `-14 / -8 / -4 / 0`。
> 只存课程级数字会得到一个"45% 一致度"的假数字，用它引用任何一本都会指错页。
> ⇒ 配置**以文件为第一公民**；多本书的课**拒绝**给出课程级 offset。

### 3. 断点续跑：键管身份、指纹管版本

`state_*.json` 记录「哪些块已经抽过」。判断"是否要重抽"看**内容指纹**
（页范围 + 字符数 + 首 32 字哈希），不看块键 —— 骨架重建导致章名变化时，
键变了但内容没变，靠指纹才能认出是同一段、不必重抽。

### 4. 引用核验必须逐字，数字尤其

`kb.verify_quote(quote, body, strict_numbers=True)`：数字未逐字命中时**直接拦下**，
不走"前缀宽容"通道。这条是有代价的（通过率会降），但数字错误是复习材料里最贵的错误。

## 四、为什么有这些守卫

下面六条说的是同一件事的另一面：**如果不这样做，会出什么后果**。
每一条在代码里都有对应的守卫，改代码时不要绕过。

- **页码范围必须带文件身份**：多本书的页码各自从 1 重编，若只用页号做键合并多本书，
  后写入的书会覆盖前一本，页会静默丢失 —— 而且没有任何地方会报错。
  ⇒ 按 `source_file` 分组建块，`chunk_id` 带文件标签。

- **批次标识必须是运行开始时一次性分配、与内容无关的值**：若拿「逐段生成的时间戳」
  这类随内容漂移的字段当批次标识，按批次清理数据时就会删掉不属于该批次的行。
  ⇒ 引入 `run_id`；**删行前必须先备份**已成规则。

- **主键不能编进位置序号**：骨架重建会让位置序号变化，主键跟着变，重抽出来的行
  就对不上旧行，断点续跑随之失效。⇒ 主键改为内容/位置派生（`course::fTAG::pA-B`）。

- **附录不能按「非正文材料」一刀切**：附录 / 附表是数值表最密集的区域，
  整章跳过会让这一章的数值表完全进不了抽取范围。⇒ 附录归类判据收敛到
  `classify_kind` 一处；一致性与台账会**报出**被跳过的页数，而不是让它无声消失。

- **引用归一化必须折叠合字**：英文教材 PDF 的文本层使用 `ﬁ/ﬂ` 等合字，
  而模型引用时写成普通 `fi`/`fl`；不折叠，逐字核验会把正常引用判成 `fabricated`。
  ⇒ 归一化补 NFKC + 去组合符号（这一步能把全库引用精确率从 92.46% 提到 95.09%）。

- **文本必须按 `utf-8-sig` 读**：带 BOM 的文件用 `utf-8` 读会让首行解析失败，
  而首行又会被「坏行跳过」逻辑吞掉，整份文件读成空。⇒ 统一 `utf-8-sig`
  （对无 BOM 文件行为不变）。

## 五、扩展点

| 想做什么 | 改哪里 |
|---|---|
| 换解析 / OCR / 转写实现（含云端） | `tools/engines/` 加一个实现 + `00_配置/engines.json` 指过去 |
| 换 LLM | `00_配置/.env` 的 `DEEPSEEK_*`（任何 OpenAI 兼容端点） |
| 调切块大小 | `kb.CHUNK_MAX_CHARS`（退化路径）/ `kb.CHUNK_EXTRACT_MAX_CHARS`（生产路径，**两个名字不同是有原因的**） |
| 加一门课 | `00_配置/courses.json` + 把素材放进 `10_原始归档/规范教材/<课程名>/` |
| 规范而不是课 | `00_配置/references.json`（单列「规范条文库」口径，不进课表） |
| 标注"这批知识点是试跑的" | `00_配置/experimental-batches.json`（按特征匹配，不写死 id；M6 默认排除） |
| 换台账口径 | `tools/consistency.py` |

## 六、自检体系（改代码后请全跑一遍）

```powershell
python -m firekb selftest      # 单元自测：原语不变式 + 引擎层 + 出境纪律
python -m firekb doctor        # 环境 + 引擎 + 契约 + 一致性 + 单元自测
python -m firekb consistency   # 多口径台账（0 矛盾才算健康）
python -m firekb schema        # 产物契约校验
```

`doctor` 退出码：`0` 全过；`5` 硬门槛失败（**必须处理**）；
`6` 仅"可选引擎未就绪"（例如没装 whisper —— 不承担转写的机器上属正常）。
